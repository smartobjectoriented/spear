# Server-side embedding worker — the generic dependency set.
#
# Everything needed to load a sentence-transformer and encode, and nothing
# else. In particular NOT chromadb and NOT the client's dependency set: the
# collection, the chunking and the retrieval semantics stay on the client, so
# the machine that only encodes should not carry a vector database to do it.
#
# UNPINNED, and that is the right default. SPEAR does not know what card,
# driver or CUDA version a deployment has, and a pin chosen here would make
# the project quietly CUDA-13-specific for everyone. Install this and let the
# resolver pick what suits the host.
#
# If you would rather reproduce a stack that has actually been measured, use
# constraints-reds-tested.txt beside this file. It records one deployment's
# exact versions and the extra index the torch build comes from, and the
# equivalence gate that was run against it.
